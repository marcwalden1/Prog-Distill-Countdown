# Co-distillation stage: Qwen3-0.6B-Base <-> Qwen3-4B-Base (design, 2026-11-10)

**Goal.** Bring the 0.6B and 4B base models to the *same* policy before each goes
through its own RL stage separately. No reward and no RL in this stage; it is pure
distillation between the two models, anchored to the initial 4B.

Code: `scripts/codistill.py` (standalone torchrun trainer, not verl) launched by
`scripts/train_codistill.sh`.

## Design decisions

| Item | Choice | Why |
|---|---|---|
| Placement | Both models on one 4-GPU node, phases run one after another | Peak memory is the largest phase, not the sum; estimated faster than a 2+2 GPU split because the 4B update dominates and scales with GPU count |
| Trainer | Own torchrun loop: FSDP2 for the two trainable models + unsharded bf16 copies of A, B and the frozen anchor on every GPU; HF `generate` for rollouts | verl's trainer assumes one trainable model; two vLLM engines in one process are risky; the bf16 copies double as frozen targets with no communication |
| Mutual loss | Full-vocabulary generalized JSD, beta = 0.5 (symmetric, bounded by log 2) | Dense signal per rollout; stable when the two distributions are far apart |
| Targets | Partner's distribution recomputed every gradient step from its pre-step bf16 copy (Jacobi) | Both models move every step, so a cached target goes stale |
| Anchor | Forward KL(P_4B0 \|\| P_self) for **both** models, 4B0 = frozen initial 4B; weight decays linearly from 1.0 (= mutual weight) to 0 over the run | Stops the mutual objective drifting to a degenerate shared policy; the decay lets the models settle together later |
| Rollouts | 256 prompts/batch, 2 rollouts per prompt from **each** model; each model trains on all 4 | Agreement wherever either model would go; same per-step cost as 4 rollouts from one model |
| Set weighting | Loss averaged within each rollout set, then 50/50 across sets (`--set_weight_a`) | The 0.6B writes longer responses and would otherwise dominate a plain token average |
| Reuse | `GRAD_STEPS_PER_GEN=4` full passes over each batch (verl's `ppo_epochs` analogue) | Spends less time generating; 10 risks overfitting the batch and stale rollouts |
| LR | `LR_A`, `LR_B` separate, both 1e-6, constant; AdamW wd 0.01, grad clip 1.0 | Repo GRPO default |
| Lengths | Prompt cap 128, response cap 384 (total 512, matches the earlier Qwen3 4B->0.6B distillation's `MAX_TOTAL_LEN=512`), temperature 1.0, truncated rollouts kept and trained up to the cap | Base models are mostly short (n=3,4 at T=0.6: median 67 / 20 tokens for 0.6B / 4B; 26% / 10% exceed 512) |
| Prompts | `balanced-simple`, raw text, no chat template; stop only at EOS | Same as the Qwen3 GRPO and distillation runs and zero-shot eval |

Checkpoints: `$CHECKPOINT_DIR/checkpoints/{Qwen3-0.6B-Base,Qwen3-4B-Base}/<EXP>/global_step_N/`
as merged HF dirs (bf16), readable as-is by `eval.sh` and as `MODEL_PATH` for GRPO.
`global_step` counts **outer** steps (generations); optimizer updates = 4x that.

Logged per batch: per-set JSD, KL(A||B), KL(B||A), KL to the anchor, entropy
(`train_k0/*` = before the batch's first update, `train_k3/*` = before its last),
rollout accuracy / length / truncation per model, grad norms, timing, peak memory.
`val/*` = the same on 256 fixed test prompts (1 rollout per model) every 50 steps.
Convergence = val KL(A||B) and KL(B||A) plateauing.

## Verification so far

- Loss functions (CPU): JSD matches an explicit-mixture reference at beta in
  {0.1, 0.5, 0.9}, is symmetric at 0.5, is zero for identical inputs, stays at or
  below log 2, its autograd gradient matches finite differences, and it stays finite
  on extreme fp32 logits.
- Packing (CPU, Qwen3-0.6B): left-padded + `logits_to_keep` log-probs match an
  unpadded forward to within 6e-5 on every response position.
- Smoke test (2 outer steps at full batch, micro-batch 4, 4 x H200): job 59612354, OK.
  44.9 GiB peak; ~206 s per outer step (32 s generation, 4 x 43 s updates). HF
  checkpoints save and are in the layout eval.sh expects. At step 0, KL(4B0 || 4B) = 0
  exactly and KL(4B0 || 0.6B) = KL(B || A), as expected.

Steps 0-450: the two models converge mostly by the 0.6B moving toward the 4B (KL to
anchor of the 0.6B falls, the 4B's stays small). Once the anchor weight falls below
~0.03 (step ~485), a runaway starts: both entropies climb every step (train_k0
ent_B 1.30 at step 459 -> 2.08 at step 500), the 4B's KL to its initial weights
quadruples, and the KL between the models drops fast because both are flattening
toward each other, not because they agree on a good policy. Mutual JSD with no anchor
has a degenerate minimizer (both models broad and identical), and the run is heading
there. The step-450 drop in KL on wandb is partly this effect.

Consequences: the anchor-0 extension (59814562) would continue the runaway, so it is
held (`scontrol hold`) pending a decision. global_step_500 is already off-distribution
(entropy ~2x); global_step_400 is the last checkpoint before it. Only the latest full
state (step 500) exists, so a clean restart from 400 means fresh AdamW.
